# Contributing

Contributions are welcome after the public foundation is promoted to an active implementation project.

Every change must preserve the kernel boundary:

- no product-specific application or governance corpus;
- no moving Git references in evidence;
- no delimiter-based command parsing;
- no promotion from prose assertions;
- no hidden network, credential, or write capability;
- no replacement of deterministic validation with model opinion.

Submit focused changes with tests and machine-readable evidence. Security reports belong in private vulnerability reporting, not public issues.
